# 拼多多多多进宝：从零到拿到 3 个凭证

目标：拿到 `PDD_CLIENT_ID` / `PDD_CLIENT_SECRET` / `PDD_PID`，让 `shopping-mcp` 的拼多多适配器切到 live。

流程分三段：**资质入驻 → 建应用 → 多多进宝绑定**。第三段不做，API 权限是空的——这是最常见的卡点。

> **可信度标注**
>
> - **第一段已在真实页面逐屏核对**（登录 → 控制台 → 资质信息 → 入驻表单 → 填表页字段）。
> - **第二、三段需要入驻审核通过后才看得到，尚未核对**，届时按实际页面补。
>
> 平台会改版，以你当下看到的页面为准。旧版社区文档说的「开发者类型选第三方开发者 / 应用类型选多多客联盟」**已经不是当前界面的口径**。

---

## 第一段：资质入驻（审核通过才能建应用）

1. 打开 <https://open.pinduoduo.com>，手机号注册并登录。
2. 导航栏点 **控制台** → 左侧 **资质信息**。未入驻时页面显示「您还没有入驻开放平台，入驻完成后可使用完整功能」。
3. 点 **立即入驻**。这一步要选**两组**东西：

   | 选项组 | 选什么 | 说明 |
   |---|---|---|
   | 开发者角色 | **多多进宝推手** | 做导购/带货。另外四个（电商软件服务商、商家服务商、拼多多商家、快团团团长）都另有用途 |
   | 入驻组织资质 | **个人开发者** | 不需要营业执照；企业开发者要企业资质 |

   ⚠️ 页面红字：**「一个主体只能入驻一次，请谨慎选择入驻资质」**——不可逆，别手滑。

4. 点 **下一步**，进入个人开发者填表页。需要准备：

   | 字段 | 要求 |
   |---|---|
   | 认证业务 | 下拉多选，当前只有「多多进宝推手」一项，勾上 |
   | 开发者身份证类型 | 中国大陆居民身份证（默认已选） |
   | 上传身份证件像 | **人像面 + 国徽面**，两张照片 |
   | 开发者姓名 | 与身份证一致 |
   | 开发者身份证件号 | 18 位 |
   | 证件有效期 | 起止日期（长期有效也要填） |
   | 联系邮箱 | 常用邮箱 |
   | 手机号 | 用于接收短信验证码 |
   | 图形验证码 | 页面上的 4 位字符 |
   | 短信验证码 | 点「获取验证码」后填 |

5. 全部填完 → **提交** → 等审核。
6. 审核通过后，控制台才会出现「我的应用 / 创建应用」入口。

## 第二段：建应用（拿 client_id / client_secret）

> ⚠️ **尚未核对**：要等入驻审核通过才能看到真实界面。

7. 控制台 → 我的应用 → 创建应用。
8. 应用信息：
   - 回调地址：填 `https://www.pinduoduo.com` 即可（官网地址可不填）
   - PRD 文档：下载模板后**什么都不用改**，直接导出 PDF 上传
9. 提交**安全扫描并发布**，测试账号填「无」。
10. 应用详情页复制：
    - `client_id` → `.env` 的 `PDD_CLIENT_ID`
    - `client_secret` → `.env` 的 `PDD_CLIENT_SECRET`

## 第三段：多多进宝后台绑定（拿 PID + 开通 API 权限）

> ⚠️ **尚未核对**：同样需要入驻审核通过后才看得到。

**跳过这段 = 调接口全部报权限错误。**

11. 打开 <https://jinbao.pinduoduo.com>（多多进宝）。入口是**「手机号免注册登录」**——手机号 + 短信验证码，首次登录即自动完成注册，不用单独走注册流程。
12. 在页面上输入上一步的 `client_id`，把应用与多多客账号**绑定**。
13. 绑定成功后，多多客 API 权限才会挂到这个应用上。
14. 在多多进宝后台找**推广位管理**，创建或查看推广位，复制 **PID** → 填进 `.env` 的 `PDD_PID`。

## 填完之后

```powershell
cd F:\DeepSeek\DeepSeek-Workplace\DSH-Workplace-01\shopping-mcp
Copy-Item .env.example .env     # 第一次才需要
# 编辑 .env，填上面三个值
```

然后跑凭证验证（会真的发一次请求，很便宜）：

```powershell
uv run python scripts\probe_creds.py
```

它会告诉你：
- 拼多多是否已经切到 `live`
- 如果失败，是**签名错误**、**权限不足**还是**PID 不对**（这三种报错长得不一样，脚本会把原始错误打出来）
- 成功时打印原始返回的字段名 + 归一化结果，用来核对字段映射

把 `probe_creds.py` 的输出贴给我，我按真实返回校准 `adapters/pdd.py` 的字段映射。

## 常见报错对照

| 报错关键词 | 含义 | 处理 |
|---|---|---|
| `sign` / 签名错误 | client_secret 填错，或多了空格/引号 | 重新复制，确认没有首尾空格 |
| `权限` / `permission` / `不支持的接口` | 第三段没做，或应用未发布 | 回步骤 11-13 绑定多多进宝 |
| `invalid pid` / `p_id` | PID 不对 | 在多多进宝推广位管理里重新取 |
| `client下线` / `clientId不正确`（code 10016） | 应用未上线或 client_id 错 | 确认应用已发布；核对 client_id |
